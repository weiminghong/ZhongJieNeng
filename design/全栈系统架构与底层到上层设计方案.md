## 1. 交付目标和边界

用户在同一工作台完成：选择数据版本 → 构建训练切片 → 训练候选 → 同口径评估 → 调用候选推理 → 复核问题 → 形成新切片和重训任务 → 人工批准或拒绝 → 切换研究展示主版本 → 出现问题时回滚。每次操作保留输入、输出和操作者证据。

首条可执行主链使用 GB10 已有山东公开市场数据，先实现日前截止下的实时电价研究模型。它是五类业务任务所需的电价基础组件，不代表五类任务全部完成。研究版本的启用状态为 `research_active`，不得冒充场站生产发布。

现有 React/Vite、FastAPI、SQLite、ECharts 和 DESIGN.md 语义颜色继续使用。001—004 迁移及既有数据不改，新增迁移从005开始。不得修改 vendor 和 short-drama-production 内部代码。

## 3. 业务上下文与任务边界

所有对象绑定 `scope_id`，其类型为 `public_market` 或 `site`。公开数据 scope 使用数据集ID和山东市场；场站 scope 使用 station_id 和对应市场/气象映射。不得创造虚假的场站或容量来容纳省级数据。

| 业务任务 | 输出 | 本轮设计中的实现条件 |
| --- | --- | --- |
| 日前功率 | 96点MW及分时MWh | 区域公开出力可作研究基线；场站预测须补气象、配置与设备状态 |
| 日前电价 | 96点元/MWh | 只使用日前价格非空样本，单独冻结可用日期，不能补造缺失标签 |
| 申报前价差 | RT预测−DA预测 | 两个价格模型必须同截止、同目标、同版本信息条件；不得输入目标日实际DA |
| 日内功率修正 | 基线+残差及适用时段 | 需要真实滚动更新的功率、气象和运行信息；不能改名复用静态曲线 |
| 日内价差 | RT预测−已公布DA | 须核实DA公布时点，保留新增信息标识 |

首条电价组件 `rt_price_day_ahead_reference`：D日96点实时价格，截止D−1日09:00，北京时间。仅以D−2及更早的价格和确定性日历构造特征；不使用目标日实际功率、负荷、DA、RT或来源预测列。输出单位为元/MWh，不能套用现有96点MW适配器。

公开文件只有事件时间，本轮采用声明的历史事件时序假设，输出 `time_policy=historical_assumed`、`production_eligible=false`。不把推断时间戳写成 verified_arrival。严格PIT任务保留 `available_at<=cutoff` 的原有约束。

## 4. 一条操作链，而不是独立按钮

| 阶段 | 人的操作 | 系统执行和输出 | 下一个入口 |
| --- | --- | --- | --- |
| 数据版本 | 选择已有源版本 | 校验哈希、字段、时间口径、缺失；登记不可变版本 | 构建切片 |
| 训练切片 | 选择任务及已冻结切分 | 生成特征矩阵、标签、行号/排除清单、拟合范围；写入服务器产物 | 启动训练 |
| 候选训练 | 提交受预算约束任务 | 后台工作进程执行；显示真实阶段、PID归属、耗时与日志；生成权重、特征协议和哈希 | 查看评估 |
| 评估对比 | 打开候选与基线 | 相同信息、样本、预算和指标；显示覆盖率、误差、分日差额及区间 | 推理/影子观察 |
| 调用推理 | 选择目标日及允许截止 | 调用真实权重；输出模型版本、训练截止、96点结果和输入证据 | 选择异常点 |
| 人工复核 | 对预测/原始记录填写原因 | 保存类型、行号、预测ID及可否用于后续训练；未知根因保持未知 | 提议改进 |
| 候选重训 | 从复核发起版本化改进 | 复制父合同，明确样本排除或允许的参数变化；在数据实际变化时生成新切片，并创建新任务、新候选 | 同口径评估 |
| 审批启用 | 查看证据后批准/拒绝 | 检查同域、同任务、评估门槛和产物可加载；追加决策，切换研究主版本 | 监测/回滚 |
| 回滚 | 选择前一个有效主版本 | 校验原权重，追加回滚事件，恢复指针；旧预测和评估不改 | 继续监测 |

候选没有改进时，正确结果是保留结果、拒绝晋升并继续复核。不能为了展示流程而改阈值、隐藏失败或伪造提升。

## 5. 状态机与真实失败反馈

### 训练任务

`queued → preparing → training → evaluating → succeeded`

分支：`preparing/training/evaluating → failed`；排队可取消；运行中只取消经核实归属的本任务子进程。服务重启后，未确认退出的任务进入 `interrupted/unknown_exit`，不得当成成功。

进度以阶段、已处理样本数、训练迭代数和验证项表示；没有可靠总量时只显示阶段与耗时，不显示虚构百分比。首条Ridge没有优化器恢复语义；中断后重试生成新attempt，从原切片重新训练。

### 模型

`candidate → evaluated → shadow → research_active → retired`

失败分支：`candidate/evaluated/shadow → rejected`。回滚追加事件，使此前已批准且可加载的版本重新成为 `research_active`。公开研究模型没有直接进入生产状态的入口。

### 复核

`draft → submitted → confirmed/rejected → incorporated_in_dataset`

保存备注不等于确认训练可用。确认者、理由、父预测、源文件版本、原始行必须完整；测试集反馈不得进入同一测试集的候选开发。

## 6. 数据、特征与评估合同

### 切分在训练前冻结

| 分区 | 目标日期 | 用途 |
| --- | --- | --- |
| 训练 | 2024-01-08—2025-08-30 | 仅此区间拟合预处理器及权重 |
| 调参验证 | 2025-09-01—2025-09-29 | 选择已声明参数，记录所有尝试 |
| 晋升比较 | 2025-10-01—2025-11-29 | 候选与主版本配对比较，可用于迭代，必须披露重复选择 |
| 锁定终评 | 2025-12-01—2026-01-14 | 候选哈希冻结后一次终评；不可反复看结果再改候选 |

当前数据缺少后续新时段，终评打开后不能把同一分区继续称为全新独立测试。模型改进与多轮候选选择使用前面的开发分区，最终效果报告记录终评使用次数。

首批特征13项：D−2、D−3、D−7同一时段RT；D−2日RT均值/最小/最大；D−7日RT均值；时段、星期、月份的sin/cos。标准化与缺失填补仅在训练分区拟合，缺失指示保留；缺失标签排除，清单保存。不得使用 serving_* 宽表或目标日实际值。

训练、调参与晋升分区之间各留一天，确保上一分区最后一天的标签在下一区间首个预测截止前已经结束。评估同时校验训练标签截止与参数选择截止；公开数据仍不因此变成已核验到达时间的PIT数据。

重训如果纳入了较晚的反馈标签，比较窗口必须移到新训练/选择截止之后；不能再把被用于改进的旧窗口当独立测试。仅调参数时复用原切片，只有源、特征、样本或切分变化才创建新数据版本。

完整切片构建后，记录各区间实际行数、全部样本ID、缺失/排除原因及预测覆盖。现在不编造尚未构建的有效样本数。

- 原始标签：源文件实时价格，单位元/MWh；不生成代理标签。
- 候选：NumPy Ridge，float64、alpha=1固定首轮；预处理、特征次序、权重均可加载验证，禁止pickle。
- 基线：D−2同段、D−7同段、训练集按星期×时段的价格中位数。
- 比较：所有方法使用同一可评价mask，同时报告全目标范围的覆盖与各自缺失，不能通过少预测降低误差。
- 主指标MAE，辅指标RMSE、MBE、负价/尖峰切片。不得对可接近零或负的电价滥用MAPE。
- 不确定性：以交易日为配对单位统计误差差额和区间；96个时段不当作96个独立交易日。
- 区间模型单独进行覆盖率与宽度校准；首条点预测不伪造P10/P90带。
- 价格允许负数，不沿用功率适配器的零值裁剪或容量上界。模型协议同时校验task、单位、目标区间和特征次序。
- 源文件哈希与特征值哈希分开。篡改目标日标签可能改变源版本和事后指标，但不得改变固定权重的输入特征值及预测值；该测试不以“完整文件哈希必须相同”为判据。
- 首轮CPU单任务、1个工作进程、4个计算线程上限、30分钟硬超时；无需GPU。实际资源峰值与耗时由执行记录产生，不预报为已测值。
- 功能闭环验收和模型效果结论分开；基线获胜也必须完整保留结果。

## 9. 后台任务和自动研判

- HTTP服务只校验和入队；持久化工作进程执行数据构建、训练和评估。首期仅一个CPU训练槽位，使用共享锁和幂等键串行入场。
- 工作进程属于 cecep-storage.service 的受控子进程，验证PID、父子关系与心跳。服务中断后核对真实输出和进程，不复制启动同一任务；任何未知退出保持unknown。
- 原始文件只读；中间结果进入runtime下任务专属目录。权重和manifest先写事务临时目录，加载/哈希/预测协议通过后原子提交，旧产物保留。
- 文件版本变化触发质量检查和当前主模型推理；没有新的源版本不制造新行情。历史回放触发单独标注research_replay的推理，不能伪装成实时到达。
- 定时监测按policy版本执行，检查缺失、价格/误差异常及推理健康。阈值进入统一配置，不再散落在代码。
- 研判卡给出异常时段、调用模型、计算结果、证据与建议。默认只提议候选重训；实际重训需要已配置的预算及明确任务授权，不无限循环消耗资源。
- Agent使用受约束的工作流调用注册模型、数据、评估和情景工具；大模型解释任务与选择工具，数值由确定性程序产生。没有可用模型时说明缺口，不读数据集预测列冒充现场推理。

## 10. 页面布局与交互

沿用既定浅绿白底、左侧导航、中央图表、右侧证据/动作。全局绑定数据域、任务、源/模型版本、目标日、读取截止；URL保留范围。

1. 数据与版本：原始覆盖和缺失 → 选择冻结切分 → 查看完整切片清单 → 构建。按钮旁说明本次会创建什么对象。
2. 训练任务：只列真实任务；阶段、耗时、预算、日志和失败重试可见。重试不覆盖原失败记录。
3. 模型评估：候选/主版本/基线同一图和指标表；显示共同mask、覆盖、训练/验证/终评区间。源文件预测列单独标注，不纳入公平对比冒充本项目模型。
4. 预测分析：选择注册模型后“运行预测”，先显示任务状态，再绘制真实返回曲线；显示权重版本和训练截止。点击异常点联动原始证据和人工复核。
5. 人工复核：草稿绑定版本与记录；提交、确认、纳入新切片分开。提供“从已确认反馈提议重训”，明确继承哪些参数、修改哪些样本。
6. 审批与回滚：对比报告、门槛、模型可加载状态、审批理由同屏。批准/拒绝均留痕；研究主版本切换与生产发布分开。
7. 智能体：回答呈现实际调用模型、输入范围、专业图表、数值工具结果和来源；动作包括叠加预测、打开评估、提交复核、查看重训提案，不能点击后无结果。

空状态说明缺哪类输入；错误保留用户参数并给真实原因。结果未就绪时不把旧指标当新结果。运行、失败、取消、拒绝、回滚各自可回到对应任务及证据。

## 11. 验收用例与完成定义

首条主链必须产生以下真实对象并校验：

- 一个冻结的数据版本和完整切片/排除清单；原文件哈希保持不变。
- 一个由真实训练产生、可重新加载的权重；修改目标日实际标签不能改变此前预测特征和预测值。
- 三个基线和候选在同一评估mask上的预测与指标；覆盖不足不能隐藏。
- 一次真实96点价格推理，caller、单位和模型ID正确；不得返回MW协议或来源预测列。
- 一条与真实预测绑定的人工复核；明确的重训提案、新切片、新候选及真实评估。
- 一次基于真实证据的批准或拒绝。晋升失败不得改门槛；审批/回滚路径由独立synthetic功能夹具验证，不能冒充实际模型提升。
- 在至少两个已批准研究版本存在时，执行回滚并验证后续推理确实使用旧权重；旧结果、源记录与审批历史保留。
- 取消、加载损坏、服务重启、重复提交和源版本变更都能得到可追溯状态，不误杀其他任务。
- 前端逐项操作与API、数据库、服务器产物一致；不得以按钮存在、测试通过或进程存活替代完成证据。

首轮完成可以得到“工作流闭环可运行”的结论；“模型有业务增益”“可用于浙江生产”“五类预测全部完成”需要各自独立证据。

## 12. 实现顺序

A. 数据/任务/模型/评估注册和005迁移 → B. NumPy候选与三个基线的CPU工作进程 → C. 真实价格推理和对比页 → D. 复核到重训提案与审批回滚 → E. 新数据/定时研判与故障恢复 → F. 在相同对象体系扩展其余任务。

先交付一条完整纵向链路，再扩展模型种类；不能先做五套空任务页面。本设计之后的实际训练、模型效果与上线情况分别记录，训练产物、测量值和发布状态以实际验收收据为准，不以设计文字作为完成证据。


## 13. 首条链路的实际实现映射

物理表使用005迁移中的 `ml_object`、`ml_job`、`ml_event`，各业务对象以kind分型，所有状态追加保存，不创建无调用方的空表。上节的细分资源接口在首期合并为 `GET /api/v1/ml/overview`、`capabilities`、`objects/{id}`、`jobs/{id}`、`lineage/{id}`，写操作统一为 `POST /api/v1/ml/commands` 的受限action。任务状态与对象ID仍独立绑定，不接受任意执行代码。

`learning.py` 实现完整行清单、历史特征、train-only预处理、真实Ridge、三个基线、同掩码误差和移动块区间、权重重载与96点推理。`ml_worker.py` 为服务内单CPU槽位控制器，API监测其退出，任务重试保留旧记录；服务未知旧退出不得重写为成功。模型记录代码commit、源哈希、特征哈希、NPZ校验及完整评估预测文件。最终窗口在显式一次性冻结前不计算指标或返回预测。

`LearningLoop.tsx` 继承现有绿色工作区，提供真实操作表单、任务阶段、候选/三个基线表、推理图、原始源行、复核、提案、审批和回滚。推理证据分析实际读取保存的模型输出；未配置外部摘要器使用确定性工具，外部失败明确返回502并留痕。

首期反馈重训只支持参数变更：复核调参窗口后，继承同一冻结数据集并改变合同允许的alpha；不构造伪标签，不新建内容相同的数据集。提升/最终窗口反馈不允许复用相同窗口选参，需要新的未来评估合同。审批条件在结果前冻结，首次仅初始化D−2研究基线；实际候选没有通过门槛时保留基线并拒绝候选。回滚成功路径由独立生成夹具验证；实际数据必须存在两个有效批准版本才执行。

源监测30秒检查已有文件版本，版本变化保存质量快照并尝试研究主模型推理与证据分析；不存在新版本时只更新时间检查，不生成新数值。输入新源需显式绑定输入哈希，训练源哈希另存，不混进旧模型评分。最终审计封存和模型协议仍能拦截自动推理。首期不自动启动训练；其他四类业务任务、场站生产认证、企业认证和新未来切分合同仍是后续范围。


## 14. 参考软件后的界面与业务连接
