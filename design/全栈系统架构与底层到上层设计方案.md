# 中节能光伏交易智能体 · 底层到上层全栈架构设计方案

> **定位**：面向中节能集中式光伏电站的 **量价预测 + 交易决策 + 双通道 Agent + RSI 自进化工作台**。  
> **设计原则**：在既有 GB10 底层 34 张表（`001_initial.sql`）与 PIT 防穿越引擎基础上做增量演进（**不推倒重来、不修改已应用迁移 `001`**），全部选用成熟、协议清晰、可在 GB10 单机稳定运行的开源技术栈。

## 3. 底层数据库增量设计（`002_upper_layers.sql`）

### 3.1 对既有 `001_initial.sql`（34 张表）的架构审查与保留策略
既有 34 张表做得非常扎实的点**全部保留**：
- L1 20 张表（18 原始表 + `rule_version` + `calendar_day`）的 `published_at / first_seen_at / available_at` 三时间戳与 `append-only` 触发器；
- `prediction_snapshot_contract`、`prediction_interval_contract`、`feature_cutoff_contract` 三个数据库级防穿越触发器。

但审查中发现 **4 个必须通过增量迁移 `002_upper_layers.sql` 补齐的结构缺口**（不修改已应用的 `001_initial.sql`）：
1. **状态流转问题**：`001` 对 `model_version`、`iteration_candidate`、`agent_run` 均加了 `BEFORE UPDATE ABORT`，无法直接改 `status`。应采用**追加式状态事件表**完成生命周期管理（兼顾完全审计追溯）。
2. **训练数据集切片缺失**：`feature_snapshot` 只存单次推理证据，不适合存数月训练样本，需要独立的 `training_dataset_version` 指向 Parquet 产物。
3. **交易合同与申报方案缺失**：`revenue_run/item` 缺少上游的中长期合约与多套日前申报方案表，无法做“方案对比沙盘”。
4. **RAG 知识库与 Agent 回答落盘缺失**：`agent_run` 没有 `answer_text` 和 `citations_json`，且强制非空 `snapshot_id`（无法回答纯规则问答或跨场站对比）。

### 3.3 读写分离与前端防卡顿契约（CQRS）
1. **底层真源（L1 / L3）严格 `append-only`**，保证训练回测与审计 100% 不可篡改。
2. **前端预聚合表（3 张 `serving_*`）允许幂等覆盖重算**：每当 `Store.ingest`、`prediction_run`、`evaluation_run`、`revenue_run` 写入完成时，只按受影响的 `(station_id, trading_date)` 增量重算刷新，单日重算耗时 < 20ms。
3. **查询路由分流**：
   - 日内实时与事后复盘（占前端 95% 流量）→ **直读 `serving_*` 单表，响应 < 5ms**；
   - 自定义历史时点回放（指定任意 `cutoff_at` 时光机）→ **实时走 `storage.py` PIT 引擎**，保证严格不穿越，并可按 `(station_id, date, cutoff_at)` 做短期结果缓存。
   - **严禁训练与回测脚本直接读取 `serving_*` 宽表**，模型训练永远只认 L1 + PIT 引擎生成的 L2 Parquet。

## 4. 四大上层业务引擎详细设计

### 4.1 引擎 A：模型训练、回测与预测调度引擎
1. **统一 4+1 任务规范**：
   - `da_power`（日前光伏功率，单位 MW，T-1 截止）
   - `id_power_correction`（日内功率残差修正，叠加日前基线输出更新 MW）
   - `da_price`（日前电价，单位 元/MWh，T-1 截止）
   - `prebid_spread_dir`（申报前价差方向，严禁输入目标日实际日前价）
   - `id_rt_spread`（日内实时价/价差，允许输入已公布的当日日前价）
2. **严格 PIT Dataset Builder**：
   - 输入：`(task, station_id, date_range, cutoff_rule, feature_spec_version)`；
   - 流程：调用 `storage.py` PIT 引擎拉取每个 `cutoff_at` 当时可见的 L1 数据 → 接入 `pvlib`/`solar-forecast` 计算晴空基线、太阳高度角 → 计算净负荷、滞后、爬坡、新旧预报修订量 → 过滤 `review_feedback` 中人工标记 `training_eligible=0`（如未登记限电）的异常样本 → 输出带 hash 的 Parquet 文件并登记 `training_dataset_version`。
3. **统一模型契约（Adapter Pattern）**：
   - 无论未来接入 **10 号服务器 `energy_poc` 已有模型**、还是本机训练的 **LightGBM / CatBoost / 深度模型**，全部封装成统一接口：`train(dataset_version) -> model_version`、`predict(model_version, snapshot) -> prediction_run`、`evaluate(prediction_run, label_cutoff) -> evaluation_run`。
   - **同口径对比铁律**：任何两个模型版本对比，强制锁死相同的 `(task, station_id, target_range, valid_observed_mask)`，并在界面显式区分“同信息集模型对比”与“日前 vs 日内新增信息对比”。

### 4.2 引擎 B：确定性交易规则与收益/考核沙盘引擎
- **铁律：所有电量、电费、考核罚款绝不交给大模型算，100% 由确定性 Python 模块读取 `rule_version` 参数计算。**
- **核心能力**：
  1. **多方案沙盘推演**：基于 `prediction_run`（含 `p10/p50/p90` 置信区间）+ `contract_position`（中长期锁价）+ `rule_version`（现货限价与偏差免考阈值），自动生成 3 套候选申报方案（如 `基准预测报量`、`保守防考核方案`、`价差套利方案`），写入 `bidding_plan` / `bidding_plan_item`。
  2. **收益与偏差拆解**：逐时段计算中长期结算电费、日前现货结算、实时偏差结算、超免考阈值考核罚金，写入 `revenue_run` / `revenue_item`，直接回答甲方最关心的**“模型 MAE 降低 1%，每月能多赚/少罚多少钱”**。

### 4.3 引擎 C：双通道交易 Agent + 混合 RAG 引擎
- **通道分离原则**：
  - **结构化数据（34+ 表数值）→ 走确定性 Tool Calling（1~5ms，100% 精确，强制 PIT）**；
  - **非结构化规则/机理/案例 → 走混合 RAG（BM25 + 向量 RRF 融合召回）**。
- **首批 8 个核心 Agent Tools（Pydantic 强类型入参/出参）**：
  1. `query_timeseries(station_id, table, start, end, cutoff_at)`：查实发、气象、电价原值与质量标记；
  2. `compare_forecast_versions(task, station_id, date, run_ids, cutoff_at)`：同口径对比多版本模型误差与曲线差异；
  3. `diagnose_deviation(station_id, date, top_k)`：定位最大偏差时段，自动关联同期气象突变、预报修订与限电事件；
  4. `simulate_bidding_revenue(station_id, date, plan_ids, rule_version_id)`：调用引擎 B 测算不同申报方案的预期收益与考核风险；
  5. `search_knowledge_rag(query, collections, market_code, as_of_date, top_k)`：检索 4 类 RAG 知识库（返回带文档名/章节/生效期的切片）；
  6. `inspect_data_quality_and_drift(station_id, task)`：查询最新 Evidently 质检与漂移报告；
  7. `create_review_draft(deviation_case_id, root_cause, training_eligible)`：生成待交易员确认的复核草稿（**写操作必须经人工点击确认，Agent 不越权自动审批**）；
  8. `explain_metric_or_field(term)`：读取 `storage_catalog.json` 解释业务口径与字段定义。
- **防幻觉护栏**：回答中涉及的任何数字必须来自当轮 `agent_tool_call` 输出；若数据未到达或工具返回空，明确说明“未到数/待核验”，绝不补数编造。

### 4.4 引擎 D：双轨 RSI 自进化闭环引擎
把 RSI 拆成两条可验收、可审计、绝不失控的独立闭环：

| 维度 | 轨道 1：预测模型 RSI | 轨道 2：Agent 业务经验 RSI |
|---|---|---|
| **触发信号** | ① `drift_check_run` 检出关键气象/供需漂移<br>② 连续 N 天配对误差超阈值<br>③ 累计 ≥ K 条 `review_feedback` 异常标注 | ① 交易员在 `deviation_case` 确认典型偏差归因<br>② 交易员对 Agent 回答打分纠偏<br>③ 新增/修订市场政策规则文档 |
| **改进动作** | 生成新 `training_dataset_version`（剔除人工标记异常样本/纳入最新实测）→ 重训候选 `model_version`（可调特征或超参）→ 登记 `iteration_candidate` | 将人工复核的“场景特征 + 根因 + 应对策略”结构化写成标准案例文档 → 切片写入 `rag_document` / `rag_chunk`（`collection='rsi_case'`）；必要时更新提示词版本 |
| **验证门槛** | 严格 PIT 离线回测 + 影子模式对比当前 `production` 模型，输出同口径 `evaluation_metric` 对比单 | 固定“黄金业务问题集”自动回归评测（工具命中率 + 数值一致率 + 规则引用准确率） |
| **上线与回滚** | 写入 `approval_decision`（人工审批）→ 写入 `model_lifecycle_event` 切换生效；线上表现退化时一键回滚旧版本 | 审核通过后 `rag_document.status='active'` 生效；过时规则或错误案例标记 `deprecated` 立即失效 |

## 5. 上层前端产品架构（高颜值开源重构）

放弃旧版静态 `iframe` 驾驶舱，采用 **Next.js + Tailwind CSS + shadcn/ui + TanStack Table + Apache ECharts**，构建**专业能源交易与调度工作台**（浅色高对比专业商务风为主，可选深色大屏模式）。

顶部固定上下文条：`[场站选择]` · `[业务日期 / 区间]` · `[查看模式：日内实时 / 历史回放(cutoff) / 事后复盘]` · `[数据口径标牌：合成演示 / 生产真实]` · `[右侧一键唤起 Agent 副驾驶]`

### 5.2 五大核心业务页面（首期优先前 4 块）
1. **预测总览与版本对比（首页）**：
   - KPI 卡片（已实测电量、同期预测、配对 MAE/RMSE、到数完整性、预估偏差考核风险）；
   - ECharts 主图：96 点多曲线联动（实测、日前预测、日内修正、晴空基线、`p10–p90` 置信区间带），支持鼠标框选缩放、点击任意异常时段直接高亮下钻；
   - 双模式版本对比面板：显式区分“同 cutoff 模型 A vs 模型 B”与“日前 vs 日内新增信息收益”。
2. **原始数据与血缘核验**：
   - 基于 `TanStack Table` 的高性能分时明细表（功率、辐照、温度、云量、电价、质量标记、来源版本、`available_at`）；
   - 支持按缺失/异常筛选、点击单行看完整来源批次与血缘、按当前筛选结果导出 CSV；
   - 内嵌 Evidently 数据质量与分布漂移摘要卡片（点击可打开完整中文报告）。
3. **申报策略与收益沙盘**：
   - 展示日前/实时电价曲线、价差柱图（$\Delta = P_{\text{RT}} - P_{\text{DA}}$）、中长期合约曲线；
   - 多套申报方案收益瀑布图（合同电费 + 现货收入 − 偏差考核 = 净收益）与敏感性对比表。
4. **右侧可展开 Agent 副驾驶（全局随行，也支持全屏页）**：
   - 自动继承当前页面的场站、日期、模式和**你刚在曲线上点选的异常时段**；
   - 展示**可折叠工具调用链**（调用了哪个 SQL 工具、查了哪条 RAG 规则、算了哪笔收益）+ 可点击的证据引用角标；
   - 支持一键生成“偏差复核草稿”送入人工审核。
5. **偏差审核与 RSI 治理台**：
   - 异常偏差案例列表（`deviation_case`）→ 交易员确认归因/勾选是否剔除训练样本/一键沉淀为 RAG 案例；
   - 模型版本生命周期列表 + RSI 候选提案对比单（新旧指标对比 + 审批上线/一键回滚）。
